Student Report

Technical Documentation: Student Report System

This section details the internal mechanics of the dynamic, interactive student report engine embedded within this page.

1. Data Retrieval (Fetching)

When the page loads, an Immediately Invoked Function Expression (IIFE) checks the document's loading state. As soon as the layout engine confirms the page is ready, it calls the loadStudentData() function. This function uses the JavaScript Fetch API to request an external dataset file named students.json.

2. UI Generation & Structure

Once the JSON data payload is successfully retrieved from the server, the script executes setupTableFramework(). This architecture function performs three core tasks:

  • Locates the placeholder container <div> carrying the explicit ID targetArea.
  • Dynamically structures an HTML table shell mapping to seven key property headers: ID, Name, Department, Major, Enrollment Date, GPA, and Status.
  • Appends a streamlined event-delegation listener onto the table's header tier (<thead>) to process column sorting interactions seamlessly.

3. Rendering Content

The renderTableRows() rendering block targets the <tbody> workspace element. It maps through the active records array and processes structured table rows (<tr>) string templates for each entity. Individual records pull dynamic properties like row.ID and row.Name, while explicitly evaluating and modifying floating values like row.GPA directly to a uniform two decimal places using .toFixed(2).

4. Interactive Column Sorting

The layout features built-in multi-type sorting rules orchestrated by the centralized sortColumn(index) calculation routine:

  • GPA Sort Logic: Parses and evaluates columns linearly by routing a continuous numeric subtraction matrix (Number(valA) - Number(valB)).
  • Text & Alphanumeric Logic: Runs structural evaluations using the natural string-comparison tool localeCompare coupled with the {numeric: true} parameter array, handling mixed alpha-numeric identification flags accurately.
  • State Reversal: Direction pathways are continually managed globally inside an indexable ascending tracking array. Registering a top header interaction flips the flag bit and updates the dataset order before refreshing the template via renderTableRows().

5. Framework Environment Context

The layout wrappers and core styling pipelines are generated natively by the Publii Open-Source Static CMS engine. While navigation nodes control site journeys across separate directories (such as Kayak Rentals or Online Courses), the page state relies on static hydration workflows combined with target asynchronous client logic script wrappers to support structural longevity.
